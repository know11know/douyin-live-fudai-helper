# 抖音直播间福袋挂机助手

**用于 AutoX.js 的抖音直播间福袋挂机、自动抢福袋辅助脚本。** 在你手动打开的直播间中，识别福袋入口、开始观看任务、参与成功和未中奖提示，按已识别的状态继续下一轮。

“自动抢”指自动完成支持界面的免费参与点击，**不是保证中奖，也不是绕过观看时长**。抽奖结果由平台决定。

> **先看适配条件：本发布版要求模拟器内部 1440 × 2560、DPI 640、竖屏。** 改变电脑上模拟器窗口大小不等于改变 Android 分辨率。当前内置紫色团购福袋、粉色霸王餐两类模板；导入图片只能增加福袋**入口**图案，不能自动适配所有直播间的任务面板。

[项目主页](https://github.com/know11know/douyin-live-fudai-helper) · [发布包](https://github.com/know11know/douyin-live-fudai-helper/releases) · [问题反馈](https://github.com/know11know/douyin-live-fudai-helper/issues)

## 1. 这个项目能做什么

| 场景 | 行为 |
| --- | --- |
| 直播间顶部出现支持的福袋图案 | 连续两帧识别后打开面板 |
| 面板出现“开始观看直播任务 参与抽奖”及未完成任务行 | 点击开始，等待观看任务 |
| 观看倒计时运行 | 保持等待，不重复点击开始 |
| 显示“参与成功 等待开奖”及完成任务行 | 等待开奖 |
| 明确识别到支持的未中奖弹窗 | 关闭“我知道了”，等待下一轮 |
| 面板收起、入口重新可见 | 保留本轮状态，重新打开核验 |
| 入口识别成功但面板连续打不开 | 在冷却间隔后继续尝试，没有“两次失败就停”的限制 |
| 换直播间后入口图案不同 | 可导入入口模板；面板仍需属于已支持样式 |

**不自动操作：** 付费加入粉丝团、付款、购买商品、领取或兑换奖品、验证码、账号登录、跨直播间搜索、小窗双账号。遇到已识别的中奖、付款、验证码、下播文案会停止；无法识别的画面继续监测，不盲点。

## 2. 环境与分辨率适配

| 项目 | 本发布版要求 / 验证范围 |
| --- | --- |
| 运行环境 | Android 模拟器 + AutoX.js；原基础版本在雷电环境运行验证 |
| Android 内部截图 | **1440 × 2560** |
| Android 密度 | **DPI 640** |
| 屏幕方向 | 手机竖屏 |
| AutoX | 基于 6.5.8 接口编写 |
| 抖音 | 普通抖音应用，包名 `com.ss.android.ugc.aweme` |
| 紫色团购福袋 | 内置入口、开始任务、观看中、参与成功、未中奖模板 |
| 粉色霸王餐 | 内置对应任务及结果模板，包含 3 分钟任务界面素材 |
| 1080×1920 / 900×1600 / 720×1280 | **本发布版不支持，启动时拒绝运行** |
| MuMu、其他 Android 系统或其他 DPI | 未验证，不承诺可用 |
| 实体手机、小窗、分屏 | 本发布版未适配 |

### 为什么分辨率和 DPI 都要一致？

识别依赖模板像素及屏幕区域。即使宽高比例相同，DPI、字体大小、显示大小、抖音界面布局变化也会改变按钮尺寸及位置。仅缩放模板无法保证正确识别。

本发布版会检查屏幕宽高、系统密度及截图尺寸；不匹配就停止。检查通过仍不代表所有抖音版本和所有直播间都已适配。**不要通过修改配置中的数字来冒充已适配。**

### 雷电设置

1. 打开模拟器设置 → 显示 → 手机竖屏。
2. 选择 **1440 × 2560（DPI 640）**；若需自定义，三个数值都保持一致。
3. 保存并重启模拟器。
4. 保持系统默认字体大小、显示缩放，关闭分屏和小窗。
5. 打开目标直播间，确认该账号确实显示福袋入口。

若手机有福袋、模拟器没有，脚本不能凭空创建入口。先确认同一账号、同一直播间、抖音版本和实际活动条件。

## 3. 安装与第一次启动

### 准备 AutoX

从 [AutoX.js 社区发布页](https://github.com/autox-community/AutoX/releases/tag/v6.5.8) 获取适合模拟器 Android 架构的 6.5.8 安装包；其他版本需要另行验证。本项目提供脚本 ZIP，**不包含 AutoX APK，也不是可独立安装的 APK**。

安装后在 Android 设置中允许 AutoX 的无障碍服务和访问脚本所在文件夹所需的存储权限。运行时出现录屏授权，选择**整个屏幕**。不同 Android 版本的权限名称可能不同。

### 导入项目

1. 下载本仓库发布的 ZIP，解压完整文件夹。
2. 将整个 `douyin-live-fudai-helper` 文件夹传入模拟器，例如：

   ```text
   /sdcard/AutoX/scripts/douyin-live-fudai-helper/
   ```

3. 在 AutoX 中设置或浏览到对应脚本目录，进入项目文件夹。
4. 确保 `main.js`、`runner.js`、`lib/`、`assets/` 都在；**只复制一个 JS 文件无法运行**。
5. 手动打开抖音目标直播间，提前完成你愿意接受的入团等参与条件。
6. 在 AutoX 运行 **`main.js`**，选择“只识别测试”。授权整个屏幕后切回直播间，查看 AutoX 日志中的识别状态。
7. 测试符合预期后再次运行 `main.js`，选择“启动自动参与”，确认真实点击并授权截图，再切回直播间。
8. 脚本最多等待约 60 秒让抖音进入前台；超时退出，需要重新启动。

“只识别测试”是**单次扫描**，不会自动点击，也不会持续挂机。实际参与必须选“启动自动参与”。请勿反复启动多个自动化脚本。

## 4. 导入不同直播间的福袋入口图片

### 从哪里进入？

运行 `main.js` → **“导入 / 管理福袋入口图片”** → “导入图片”。也可以直接运行 **`导入福袋图片.js`**。

操作界面包含文件浏览器，可以从 `/sdcard/Download` 开始进入文件夹选择 PNG / JPG；也支持输入**模拟器内的完整文件路径**。例如 `C:\Users\...` 是电脑路径，不能直接作为 Android 图片路径。

### 准备图片

- 使用模拟器**内部原始截图**，分辨率必须是 1440×2560、DPI 640；不要使用包含电脑桌面和模拟器边框的截图。
- 可导入完整原始截图，再输入裁剪坐标；也可先裁剪好入口图案再导入。
- 裁剪保留稳定、不透明的图案细节，避开倒计时、参与人数、动态图像和透出的直播背景。
- 裁剪图至少 16×16，最大 320×320；最多保存 12 张自定义入口图片。
- 一次只运行一个自动点击脚本。导入前停止**发布版**，导入后重新启动，使新清单生效。

### 坐标怎么填？

所有数值都是 **Android 原始截图像素**，格式：`x,y,宽,高`，左上角为 `(0,0)`。

示例：入口位于截图左上区域，可使用：

| 字段 | 示例 | 含义 |
| --- | --- | --- |
| 裁剪范围 | `40,430,140,120` | 从原截图 x=40、y=430 开始，截取 140×120 |
| 搜索范围 | `20,400,320,300` | 仅在这个区域寻找导入的图案 |
| 图片名称 | `某直播间入口` | 便于管理，不参与识别 |

**这些数字只是示例，必须按你的实际入口位置调整。** 若输入已裁剪图片，裁剪范围通常使用 `0,0,图片宽,图片高`。搜索范围仍填写入口在完整屏幕上的位置。

为避免误把底部商品购买按钮当作福袋入口，自定义搜索范围限制在顶部 **y=120 到 y=800** 内，不能超出屏幕。完整截图的裁剪范围必须落在搜索范围内。

确认保存后，图片存入项目自己的 `custom/entries/`，清单存入 `custom/entries.json`；不会修改内置素材。删除入口：相同菜单 → “删除已导入图片”。

### 导入后仍不点击怎么办？

1. 先运行单次识别测试，确认状态是否为 `bag_entry`。
2. 若入口为 `unknown`：检查原始尺寸、DPI、裁剪图中是否混入变化文字或背景，以及搜索范围是否覆盖入口。
3. 若能打开入口，但面板为 `panel_unknown` / `unknown`：说明任务面板还未适配，**导入入口图片不能解决按钮或结果皮肤变化**。
4. 不要随意降低匹配阈值。阈值默认 0.93；过低可能把优惠券、商品卡等错误识别成入口。

## 5. 连续挂机与重试策略

```text
识别直播间顶部入口 → 打开面板 → 识别开始按钮与任务行 → 开始观看
       ↑                                             ↓
等待下一轮 ← 关闭已识别的未中奖弹窗 ← 等待开奖 ← 确认参与成功
```

- 每轮识别后间隔约 **500 毫秒**；截图、图像匹配和系统调度也耗时，因此不是每 500 毫秒必定完成一次操作。
- 入口需连续两帧识别；两次打开尝试至少间隔 **3 秒**。已识别入口持续可见时继续尝试，不按次数停机。
- 开始任务点击未生效时，同一连续按钮状态最多重试一次，间隔至少 3 秒。看到倒计时就等待。
- 面板收起时重新打开，不清空本轮开始任务标记；不会为了检测而频繁关闭面板。
- 未中奖弹窗关闭后会核验是否消失；仍存在则停止，避免重复误点。
- 未知画面保持监测，但**不能保证面板始终打开，也不能保证每轮成功参与**。入口被遮挡、皮肤变化、系统休眠、网络异常等都可能导致漏轮。
- 不要求倒计时接近结束才开始。识别到支持的开始状态后会尽快参与；若总在临近结束才点击，应检查识别匹配与界面变化。

## 6. 如何停止、下次如何继续

**停止：** 按 Android 音量加键（模拟器需要向 Android 发送按键），或打开 AutoX → 管理 → 停止相应脚本。切出抖音可能使前台检查失败而结束，不能把切应用当作暂停后自动恢复。

**下次继续：** 打开同一或已适配的直播间 → AutoX 项目中的 `main.js` → “启动自动参与” → 确认与截图授权 → 切回抖音。导入的图片会保留，无需每次重新导入。

电脑休眠、模拟器关闭、AutoX 被系统结束、录屏权限撤销之后，脚本无法自行复活，需要重新启动。运行时保持屏幕常亮、网络正常、抖音在前台。

## 7. 常见问题

### A. AutoX 文件页是空的

检查脚本目录设置、文件访问权限，以及 ZIP 是否真正解压。项目入口位于项目文件夹中，不在 APK 内。

### B. 运行后只有识别日志，没有点击

确认选的是“启动自动参与”而不是单次识别测试；确认启动确认框已同意、整个屏幕录屏授权有效。再看日志是否为未知状态。

### C. 福袋面板被收起，一直没参与

脚本必须先正向识别入口才能打开。入口皮肤不同可导入图片；被优惠券、悬浮窗或活动覆盖时应先人工处理。它不会在完全未知的画面盲点固定坐标。

### D. 打开很慢，甚至错过观看任务

优先检查匹配状态是否经常为 `unknown`、模板裁剪是否包含变化背景、内部尺寸是否正确。电脑负载、模拟器性能和网络加载都会影响响应。每轮识别间隔不是参与成功的时间保证。

### E. 粉丝团未加入

脚本不自动支付入团费用。请自行确认参与条件并决定是否加入；不要将付款按钮作为入口图片导入。

### F. 能自动连续多少轮？

没有按轮数设定的退出上限；在支持界面、前台及权限正常的情况下持续运行。中奖、已识别阻断、截图异常等仍会结束；无限重试入口不等于永不停止。

### G. 两个模拟器 / 两个号可以同时开吗？

本项目单个 Android 实例只处理一个前台账号。不支持同一实例的小窗双开。不同实例互相隔离，但资源占用和平台参与条件需自行核对，本发布版未新增多实例调度功能。

### H. 可以直接替换旧版本吗？

建议并排保存。新项目文件夹是 `douyin-live-fudai-helper`，不覆盖旧目录；配置、导入图片和运行标记使用独立名称。**不要同时启动两个版本自动点击同一实例。**

## 9. 日志、隐私与验证范围

核心脚本没有上传账号、图片或日志的联网逻辑。日志保存在 AutoX 私有外部文件目录，文件名前缀为 `douyin-live-helper-startup-` 和 `douyin-live-helper-actions-`，可辅助排查识别状态与点击记录。长期运行会生成日志文件，需要自行定期清理已停止运行的旧日志。

仓库不包含账号登录信息、设备解锁密码、完整个人直播截图、设备私有日志或 AutoX 安装包。自行提交反馈前请检查图片中是否包含账号等个人信息。

**验证范围：** 此项目从本地已运行验证的 1440×2560 / DPI640 状态机另建；旧版有紫色与粉色免费任务参与闭环的本地运行记录。发布版新增图片导入、严格尺寸检查和独立菜单，完成离线语法及逻辑测试。**新增菜单和导入功能尚未在模拟器上端到端验证；不将旧版实测结果冒充发布版实测。** 中奖界面未完成实际中奖验证，因此不自动领奖。不同抖音版本与新皮肤可能需要继续适配。

开发者可运行：

```sh
node tests/release.test.cjs
```
